# 오픈 소스 퀴즈

객관식 15문항(각 1점)과 정부/시민 차원으로 나눈 서술형 1문항(5점), 기본 구성은 총 20점이며 관리자 문항·배점 수정에 따라 달라집니다. Python 3.10 이상을 사용합니다. 원격 저장 시 검증된 `cryptography` 라이브러리로 답안을 암호화합니다.

## 화면과 운영

학생은 `/`, 관리자는 `/admin`, O/X 연습문제는 `/practice`입니다. 관리자는 반을 만들고 중복 없는 4자리 숫자 응시 코드를 전달한 후 반별 시험을 공개·잠급니다. 공개된 반의 학생만 문항을 요청하고 답안을 제출할 수 있습니다. 서버가 잠금을 확인하며 기존 화면은 약 3초 이내 가려집니다.

객관식은 제공된 정답으로 채점합니다. 서술형 자동 제안은 핵심 표현에 기반한 참고 점수이며 의미·부정 표현을 완전히 이해하지는 못합니다. 두 칸 모두 작성하면 기본 3점, 한 차원에서 취지가 확인되면 4점, 양쪽에서 확인되면 5점을 제안합니다. 관리자는 학생별 결과를 확인하고 서술형 점수와 메모를 수정·저장합니다.

## 무료 Render 서버 + 기존 공개 GitHub 저장소의 암호화 파일

[Render 배포 설정 열기](https://render.com/deploy?repo=https://github.com/fung123-ksjeil/quiz2026)

`render.yaml`은 Free 서버를 사용하고 유료 디스크는 만들지 않습니다. Render 자체 정책에 따라 계정·결제 확인을 요청할 수 있으며 무료 서버에는 절전과 재시작, 사용량 제한이 있습니다. 수업 전 충분히 서버를 깨우고 테스트하세요.

1. 기존 `fung123-ksjeil/quiz2026` 저장소를 그대로 사용합니다. 공개 저장소여도 됩니다. 앱 코드 브랜치는 `main`, 답안 보관 브랜치는 `quiz-data`로 분리합니다. 데이터 브랜치는 연결 후 앱이 자동 생성하므로 새 저장소를 만들 필요가 없습니다.
2. GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens에서 `quiz2026` 저장소만 선택한 토큰을 만드세요. Repository permissions의 **Contents: Read and write**가 필요합니다. Metadata 읽기는 자동 포함됩니다. 기관 정책에 따라 토큰 승인이 필요할 수 있습니다.
3. Render 환경 변수에 아래 값을 입력합니다. 토큰과 비밀번호를 채팅·GitHub 소스·학생 화면에 넣지 마세요.

| 이름 | 값 |
| --- | --- |
| ADMIN_PASSWORD | 지정한 관리자 비밀번호 |
| GITHUB_DATA_REPO | `fung123-ksjeil/quiz2026` |
| GITHUB_DATA_TOKEN | 위에서 만든 토큰 |
| QUIZ_DATA_KEY | Blueprint가 자동 생성하는 암호화 비밀값. 기존 서비스에서는 32자 이상의 임의 비밀값을 설정 |
| HOST | `0.0.0.0` |
| COOKIE_SECURE | `1` |

서버는 반복되는 시험지 버전 정보를 압축한 뒤 `QUIZ_DATA_KEY`로 인증된 암호화(Fernet)를 적용한 후에만 원격 파일을 저장합니다. 이 키는 관리자 비밀번호와 별개이며 최소 32자 이상의 임의 비밀값이어야 합니다. 키를 GitHub나 학생에게 공개하지 마세요. 새 배포에도 동일한 키를 유지해야 기존 답안을 읽을 수 있습니다. 잘못된 키로 시작하면 기존 파일을 덮어쓰지 않고 중단합니다. 원격 읽기가 실패하면 빈 데이터로 시작하지 않습니다. Render에서는 GitHub 저장 설정이 없으면 시작을 중단해 임시 디스크를 영구 보관으로 오인하지 않게 합니다. 기존 Render 서비스라면 Settings에서 Free 인스턴스로 바꾸고 유료 디스크가 남아 있지 않은지도 확인하세요. 기존 디스크가 있다면 필요한 기록을 먼저 보존하세요.

`quiz-data` 브랜치의 `quiz-records.enc` 파일에 반 설정·학생 답안·채점 결과·이탈 기록을 모두 암호화해서 저장합니다. 파일명과 커밋 메시지에는 학생 정보를 넣지 않습니다. 데이터 기록이 `main`을 갱신하지 않으므로 답안 저장마다 앱이 재배포되지 않습니다. 작성 중 답안은 서버에 먼저 임시 저장하고 약 60초마다 GitHub에 일괄 보관합니다. **최종 제출, 교사 점수 수정, 반 공개/잠금, 관리자 삭제는 GitHub 저장 응답을 확인한 다음 성공 처리합니다.** GitHub 오류 시 저장 실패/보관 대기를 표시하며 서버가 재시도합니다. 무료 서버가 갑자기 종료되면 아직 원격 저장되지 않은 임시 답안은 사라질 수 있습니다. 최종 제출 완료 여부를 확인하세요. 단일 서버만 사용하며 여러 인스턴스가 같은 저장소를 동시에 갱신하지 않게 하세요.

GitHub의 API 사용량·파일 크기 제한이 있어 작은 학급 퀴즈용입니다. 암호화·인코딩된 업로드 크기가 약 950KB를 넘으면 쓰기를 거부하고 오류를 표시합니다. 실제 GitHub 연결은 사용자 계정/토큰 설정 후 검증해야 합니다. 무료/기관 계정 정책도 해당 서비스에서 확인하세요.

## 기록 삭제

자동 삭제하지 않습니다. 관리자에서 **이 학생 기록 삭제** 또는 **이 반의 학생 기록 삭제**를 누르고 확인하면 현재 스냅샷과 서버에서 답안·점수·이탈 기록을 삭제합니다. 반 전체 삭제 시 반도 잠기며 재입장이 제한됩니다. GitHub에 저장된 이전 커밋에는 암호화된 과거 데이터가 남을 수 있습니다. 과거 이력까지 삭제하려면 별도의 저장소 이력 삭제 작업이 필요합니다. 서비스 응답 실패 시 삭제 완료로 표시하지 않으며 재시도할 수 있습니다.

## 로컬 테스트

패키지에서는 `Windows_테스트실행.bat` 또는 `python3 테스트실행.py`를 실행합니다. GitHub 환경 변수 없이 실행하면 원격 암호화 라이브러리 설치 없이도 로컬 `.data`에만 저장하며 관리자 화면에 보관 모드를 표시합니다. Git 소스만 받은 경우 비밀번호를 입력하거나 `ADMIN_PASSWORD`를 설정합니다. 패키지는 비밀번호 검증 해시만 포함하고 GitHub에는 포함하지 않습니다. 기본 서버 실행은 `python3 server.py`입니다.

학생은 학번·이름을 직접 입력하며 본인 인증은 없습니다. 쿠키가 사라지면 기존 답안과 연결할 수 없습니다. 복사·붙여넣기·우클릭·인쇄를 제한하고 화면 전환 시 문항을 가려 기록합니다. OS 캡처·다른 기기 검색을 완전히 막을 수 없으며 이탈 기록은 부정행위 확정 근거가 아닙니다.

## 검증

`python3 test_server.py`로 인증·반별 잠금·답안 저장·채점·점수 수정·삭제·재시작을 확인합니다. `python3 test_github_store.py`는 모의 GitHub 응답으로 저장과 실패 처리를 확인합니다. `pip install -r requirements.txt`로 원격 저장에 필요한 라이브러리를 설치합니다. 실제 배포 환경에서는 반 생성 → 공개 → 학생 입장/최종 제출 → 교사 점수 수정 → 재시작 후 보존 → 테스트 학생 삭제를 확인하세요. GitHub Pages는 서버 코드를 실행하지 않으므로 현재 앱을 단독 운영할 수 없습니다.

이전의 긴 응시 코드는 서버 시작 시 4자리 숫자로 자동 전환됩니다. 기존 반과 답안은 유지되며 관리자가 새 코드를 확인해서 배포해야 합니다.

## 문항·정답 편집과 O/X 연습

관리자 로그인 후 메인 하단의 **문항 관리** 버튼을 눌러 별도 `/admin/questions` 화면으로 이동합니다. 메인 상단에는 반 만들기, 아래에는 반 관리·응시 현황을 표시합니다. 링크·코드 복사 기능은 제거했습니다. 시험 문항은 객관식(2~5개 선택지), O/X, 두 답란 서술형을 추가·수정할 수 있습니다. 문제·지문·배점·선택지·정답 번호와 서술형 예상 답안·핵심어를 입력합니다. (가)/(나) 연결 선택지는 `|`로 열을 나눕니다. 변경 전 모든 반을 잠가야 하며 이미 입장한 학생의 시험지와 정답은 입장 당시 버전으로 유지됩니다. 새 문항은 이후 입장한 학생에게 적용됩니다. 채점 결과·총점·진행률은 학생별 시험 버전에 따라 계산됩니다. 기존 학생의 시험지를 바꾸려면 별도 반을 만들고 새 브라우저 세션으로 입장시키세요.

반을 만들 때 4자리 응시 코드를 직접 지정할 수 있고 비워 두면 자동 발급됩니다. 기존 반의 **응시 코드 변경** 버튼으로 바꿀 수 있습니다. 중복 코드는 거부합니다.

첨부된 세 PDF에서 확인한 개념으로 중학교 3학년 수준의 O/X 30문항(상 5, 중 5, 하 20)을 작성했습니다. 최초에는 모두 공개됩니다. 난이도는 관리자 확인용이며 학생에게 선택 기능을 제공하지 않습니다. 관리자는 공개할 문항의 체크를 선택하고 **선택한 문제만 공개**를 누릅니다. 공개 변경 후 학생은 페이지를 새로고침하면 최신 목록을 받습니다. 새 연습문제의 정답과 관련 주제를 선택하고 **자료 기반 해설 초안 만들기**를 눌러 해설을 검토·수정한 뒤 저장합니다. 문제·정답·주제를 바꾸면 오래된 해설은 지워집니다.

학생은 한 문제씩 O/X를 선택하고 정답·해설·파일명·교과서 쪽수를 확인한 후 다음 문제로 이동합니다. 정답에는 긍정적인 피드백, 오답에는 구체적 해설을 제공하고 마지막에 결과를 표시합니다. 연습 결과는 현재 화면에서만 유지되며 개인정보나 시험 점수로 저장하지 않습니다.

`reference_topics.json`은 업로드된 6-1·6-2·6-3 자료를 읽고 작성한 근거 요약입니다. `practice_seed.json`은 검토한 초기 30문항과 해설입니다. 새 문제의 해설 초안은 선택한 근거 개념을 활용한 규칙 기반 초안이며 임의 문장의 의미·정오를 자동으로 판정하는 언어 모델이 아닙니다. 교사가 입력한 정답을 기준으로 하므로 공개 전에 문제와 해설의 연결을 확인하세요. 자료에 없는 내용을 임의로 추가하지 않습니다. 초기 문제는 한 번만 등록되며 이후 교사 수정·공개 설정은 재배포해도 유지됩니다. 문항 설정도 암호화한 GitHub 스냅샷으로 보관됩니다.

`python3 test_content.py`로 응시 코드 지정·변경, 문항·정답 편집, 공개 선택, 원문 자료 출처, 과거 응시 버전 보존 및 재시작 복원을 검증합니다.

## 편집 취소와 반 삭제

문항 목록에서 수정하면 편집 폼으로 이동하고 **취소 · 목록으로**를 누르면 저장하지 않고 원래 목록으로 돌아갑니다. 시험·연습문제 모두 동일하며 별도 화면의 **관리자 메인으로** 링크로 반 관리에 복귀합니다. 로그인하지 않고 문항 관리 주소를 열면 로그인 후 해당 화면으로 돌아옵니다.

반 카드에는 학생 데이터 유무·학생 수·제출 수를 표시합니다. **반 삭제**는 빈 반에도 확인을 받고, 학생 기록이 있으면 반과 해당 학생의 답안·채점·이탈 기록을 함께 삭제할 것인지 묻습니다. 확인하는 사이 기록 수가 바뀌면 서버가 삭제를 거부하므로 다시 확인해야 합니다. 삭제 취소 시 API를 호출하지 않습니다. **이 반의 학생 기록 삭제**는 기존처럼 반 자체는 유지하며 기록만 지웁니다. GitHub 과거 커밋에 남는 암호화 기록은 별도 이력 삭제 대상입니다.

## 반별 응시 현황과 엑셀

반 카드의 **응시 현황** 버튼을 누르면 해당 반의 학생 기록만 표시합니다. 입장·제출·미제출 수와 학생별 문항 정오·점수, 서술형 점수 수정 기능을 확인할 수 있습니다. **전체 반 보기**로 전체 기록을 볼 수 있습니다. 시험 상태는 **공개 중=초록색**, **잠김=빨간색**으로 버튼과 상태 문구에 표시됩니다.

현황의 **학생점수 다운로드 (.xlsx)** 버튼은 선택한 반(또는 전체 반)의 최신 저장된 채점 결과를 실제 Excel 통합 문서로 내려받습니다. 학번·이름·문항별 O/X·총점을 포함하며 서술형은 부분정답과 점수, 미제출은 빈 총점, 시험 버전에 없는 문항은 해당 없음으로 구분합니다. 반·제출 상태·만점·서술형 채점 상태도 포함합니다. 학번은 텍스트로 저장해 앞자리 0을 유지하고 이름을 Excel 수식으로 실행하지 않습니다. 자동 제안 상태의 서술형 점수는 교사 확인이 필요합니다. 다운로드는 관리자 인증이 필요하며 학생이나 비로그인 사용자는 접근할 수 없습니다.

학생이 최종 제출을 누르면 학번·이름 확인창이 열립니다. 학생이 수정하고 **확인 후 최종 제출**하면 수정 정보와 답안을 함께 저장합니다. **문제로 돌아가기**를 누르면 정보 수정이나 제출 없이 응시를 계속합니다. 제출 후에는 정보를 바꿀 수 없습니다. GitHub 보관이 확인된 제출 정보는 서버 재시작 후에도 유지됩니다.

`python3 test_scores.py`로 XLSX 구조·정오답·부분점수·텍스트 안전성을, `python3 test_content.py`로 수정한 학생 정보와 엑셀 내려받기의 인증·저장·복원을 검증합니다.

응시 현황과 엑셀에는 **제출 시각 (한국 시간)**을 `YYYY-MM-DD HH:MM:SS` 형식으로 표시합니다. 서버에 저장한 원래 UTC 제출 시각을 한국 시간으로 변환하며 날짜 경계와 초 단위를 유지합니다. 기존 제출 기록에도 적용되고, 미제출 학생의 엑셀 시각은 빈칸입니다. 점수를 수정해도 원래 제출 시각은 바뀌지 않습니다.
