# 6단원 온라인 퀴즈

객관식 15문항(각 1점)과 정부/시민 차원으로 나눈 서술형 1문항(5점), 총 20점입니다. Python 3.10 이상 표준 라이브러리만 사용합니다.

## 화면과 운영

학생은 `/`, 관리자는 `/admin`, 연습문제 준비 화면은 `/practice`입니다. 관리자는 반을 만들고 응시 코드를 전달한 후 반별 시험을 공개·잠급니다. 공개된 반의 학생만 문항을 요청하고 답안을 제출할 수 있습니다. 서버가 잠금을 확인하며 기존 화면은 약 3초 이내 가려집니다.

객관식은 제공된 정답으로 채점합니다. 서술형 자동 제안은 핵심 표현에 기반한 참고 점수이며 의미·부정 표현을 완전히 이해하지는 못합니다. 두 칸 모두 작성하면 기본 3점, 한 차원에서 취지가 확인되면 4점, 양쪽에서 확인되면 5점을 제안합니다. 관리자는 학생별 결과를 확인하고 서술형 점수와 메모를 수정·저장합니다.

## 무료 Render 서버 + 비공개 GitHub 파일 보관

[Render 배포 설정 열기](https://render.com/deploy?repo=https://github.com/fung123-ksjeil/quiz2026)

`render.yaml`은 Free 서버를 사용하고 유료 디스크는 만들지 않습니다. Render 자체 정책에 따라 계정·결제 확인을 요청할 수 있으며 무료 서버에는 절전과 재시작, 사용량 제한이 있습니다. 수업 전 충분히 서버를 깨우고 테스트하세요.

1. GitHub에서 `quiz2026-data` 같은 **비공개(Private)** 저장소를 별도로 만드세요. 앱이 사용하는 스냅샷만 보관하는 저장소여야 합니다.
2. GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens에서 위 저장소만 선택한 토큰을 만드세요. Repository permissions의 **Contents: Read and write**가 필요합니다. Metadata 읽기는 자동 포함됩니다. 기관 정책에 따라 토큰 승인이 필요할 수 있습니다.
3. Render 환경 변수에 아래 값을 입력합니다. 토큰과 비밀번호를 채팅·GitHub 소스·학생 화면에 넣지 마세요.

| 이름 | 값 |
| --- | --- |
| ADMIN_PASSWORD | 지정한 관리자 비밀번호 |
| GITHUB_DATA_REPO | `fung123-ksjeil/quiz2026-data` (실제 비공개 저장소 이름) |
| GITHUB_DATA_TOKEN | 위에서 만든 토큰 |
| HOST | `0.0.0.0` |
| COOKIE_SECURE | `1` |

GitHub 저장소가 비공개인지 시작할 때 검사합니다. 원격 읽기가 실패하면 빈 데이터로 시작하지 않습니다. Render에서는 GitHub 저장 설정이 없으면 시작을 중단해 임시 디스크를 영구 보관으로 오인하지 않게 합니다. 기존 Render 서비스라면 Settings에서 Free 인스턴스로 바꾸고 유료 디스크가 남아 있지 않은지도 확인하세요. 기존 디스크가 있다면 필요한 기록을 먼저 보존하세요.

`quiz-records.json` 파일에는 반 설정·학생 답안·채점 결과·이탈 기록이 저장됩니다. 작성 중 답안은 서버에 먼저 임시 저장하고 약 60초마다 GitHub에 일괄 보관합니다. **최종 제출, 교사 점수 수정, 반 공개/잠금, 관리자 삭제는 GitHub 저장 응답을 확인한 다음 성공 처리합니다.** GitHub 오류 시 저장 실패/보관 대기를 표시하며 서버가 재시도합니다. 무료 서버가 갑자기 종료되면 아직 원격 저장되지 않은 임시 답안은 사라질 수 있습니다. 최종 제출 완료 여부를 확인하세요. 단일 서버만 사용하며 여러 인스턴스가 같은 저장소를 동시에 갱신하지 않게 하세요.

GitHub의 API 사용량·파일 크기 제한이 있어 작은 학급 퀴즈용입니다. 스냅샷이 약 700KB를 넘으면 쓰기를 거부하고 오류를 표시합니다. 실제 GitHub 연결은 사용자 계정/토큰 설정 후 검증해야 합니다. 무료/기관 계정 정책도 해당 서비스에서 확인하세요.

## 기록 삭제

자동 삭제하지 않습니다. 관리자에서 **이 학생 기록 삭제** 또는 **이 반의 학생 기록 삭제**를 누르고 확인하면 현재 스냅샷과 서버에서 답안·점수·이탈 기록을 삭제합니다. 반 전체 삭제 시 반도 잠기며 재입장이 제한됩니다. GitHub에 저장된 이전 커밋에는 과거 데이터가 남을 수 있습니다. 과거 이력까지 삭제하려면 별도의 저장소 이력 삭제 작업이 필요합니다. 서비스 응답 실패 시 삭제 완료로 표시하지 않으며 재시도할 수 있습니다.

## 로컬 테스트

패키지에서는 `Windows_테스트실행.bat` 또는 `python3 테스트실행.py`를 실행합니다. GitHub 환경 변수 없이 실행하면 로컬 `.data`에만 저장하며 관리자 화면에 보관 모드를 표시합니다. Git 소스만 받은 경우 비밀번호를 입력하거나 `ADMIN_PASSWORD`를 설정합니다. 패키지는 비밀번호 검증 해시만 포함하고 GitHub에는 포함하지 않습니다. 기본 서버 실행은 `python3 server.py`입니다.

학생은 학번·이름을 직접 입력하며 본인 인증은 없습니다. 쿠키가 사라지면 기존 답안과 연결할 수 없습니다. 복사·붙여넣기·우클릭·인쇄를 제한하고 화면 전환 시 문항을 가려 기록합니다. OS 캡처·다른 기기 검색을 완전히 막을 수 없으며 이탈 기록은 부정행위 확정 근거가 아닙니다.

## 검증

`python3 test_server.py`로 인증·반별 잠금·답안 저장·채점·점수 수정·삭제·재시작을 확인합니다. `python3 test_github_store.py`는 모의 GitHub 응답으로 저장과 실패 처리를 확인합니다. 실제 배포 환경에서는 반 생성 → 공개 → 학생 입장/최종 제출 → 교사 점수 수정 → 재시작 후 보존 → 테스트 학생 삭제를 확인하세요. GitHub Pages는 서버 코드를 실행하지 않으므로 현재 앱을 단독 운영할 수 없습니다.
